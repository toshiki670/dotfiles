# prose-genres — このリポジトリの文書ジャンル別デフォルト

`prose-tidy` はジャンル依存の判定について手続きだけを定め、具体的な値はリポジトリごとの companion skill に委ねている。これはこのリポジトリ(dotfiles)での具体値。

このリポジトリの文書ジャンルには、正式な仕様書・チュートリアルのような「要約的な前置きが慣行として期待される」ジャンルが無い。したがって**前置きはどのジャンルでも一律「削る」**になる(`prose-tidy` 自身の観点1)。

重複と経緯・実装事情は `debt-audit` が判定するので、下の表は verdict ではなく**渡す材料**として読む。

## ジャンル別デフォルト

| ジャンル | 該当ファイル | 編集され続けるか/記録か | 経緯・実装事情のうち、残す価値があると分かっているもの |
| --- | --- | --- | --- |
| 使い方ガイド/リファレンス | `README.md`、`COLOR.md` | この先も編集され続ける | — |
| ルール集 | `CONTRIBUTING.md` | この先も編集され続ける | 分類・判断基準として機能する理由(例: 「`.claude/` 配下はホームに展開されないので `chore:`、展開されユーザー環境に影響するものは `feat:`」という基準そのもの) |
| 意思決定の記録(確定後) | commit message の body、マージ/クローズ済みの PR/Issue 本文・レビューコメント | 一度書いたら書き換えない | — |
| 意思決定の記録(レビュー中) | オープン中の PR/Issue 本文 | この先も編集され続ける(マージ/クローズまで) | Chesterton's Fence 予防・分類基準。**マージは squash なので、経緯はコミットとレビュースレッドに残る**ことも一緒に渡す |
| コード内平文コメント | `*.fish` / `*.sh` / `manifest.toml` 等のコメント | この先も編集され続ける | Chesterton's Fence 予防 |

Rust の `//!` / `///` および設計根拠を運ぶ隣接 `//` コメントは `rustdoc-tidy` の対象で、このジャンル表には含まれない。

## このリポジトリに無いジャンル

設計・内部構造の判断根拠は rustdoc に集約する方針(プロジェクト CLAUDE.md)のため、ADR のような独立した設計判断記録の文書ジャンルはこのリポジトリに存在しない。設計判断の経緯を書きたくなったら、まず「これは rustdoc の doc コメントに書くべきではないか」を疑う(該当すれば `rustdoc-tidy` の対象)。
