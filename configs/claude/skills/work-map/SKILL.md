# work-map — 作業中の理解を一枚に起こす

進行中の仕事について、経緯・状況・依存関係を単一の HTML ページへ起こす。読まれるのは**作業中に認知負荷が高くなったとき、あるいは理解が及んでいないと感じたとき**で、作業の再開時でも他人への説明用でもない。

したがってページの仕事は記録ではなく、**頭に収まらなくなったものを外に出して見えるようにする**こと。

## 方針（厳守）

- **情報は増やすのでなく構造化して減らす。** 網羅は目的ではない。いま負荷の原因になっているものだけを構造に落とす。関係する事実を全部書くと、外に出した先でもう一度同じ量に埋もれる。
- **先頭に来るのは未解決のもの。** 読み手は背景を全部知っている一方、何が未解決かを見失っている。だから既知から未知へではなく、**未解決から既解決へ**並べる。状態を持つ表も同じで、未解決の行を上に置く。
- **読み手は本人なので前提の説明を書かない。** 背景を知らない読者に向けた導入・用語解説・目的の再説明は載せない。
- **主張には出所を持たせる。** 一次情報があるならリンクにする。無い場合は何に基づくかを語で示す（下記）。
- **単一ファイル自己完結。** 外部への通信を一切行わない。CSS と JS はインライン、画像は data URI。CDN 参照が1つでもあると、ファイルを渡した先やオフラインで壊れる。
- **既定は破棄。** `~/Claude/scratch/` に置き、用が済んだら捨てる。残すよう明示されない限り、リポジトリには書かない（commit 事故になる）。
- **自分の判断で作り始めない。** 起動されたときだけ作る。

## 手順

### 1. 何が負荷になっているかを掴む

いま何が分からなくなっているのかを、会話の文脈から拾うか、短く尋ねる。**主題ではなく負荷の原因**を特定する。場面ごとに原因は決まっている:

| 場面 | 負荷の原因 | 主役の形 | 添える形 |
| --- | --- | --- | --- |
| 障害・不具合の調査 | 仮説が複数あり、どれを潰したか追えない | 仮説の状態表（生存 / 否定 / 未検証 と根拠） | 試したことの時系列 |
| 大きい実装の進行管理 | フェーズが多く、何で止まっているか見えない | 進捗の状態表 | ブロック関係の有向グラフ、残数 |
| 既存システムの把握 | 依存とデータフローが頭に入らない | 有向グラフ | 構成要素の表 |
| 設計の検討・意思決定 | 制約と帰結が連鎖し、選択肢が絡む | 有向グラフ（前提 → 帰結） | 論点表、決定の時系列 |
| 他人の成果物のレビュー | 指摘が散在し、重要度と対応状況が混ざる | 指摘の状態表 | 該当箇所の一覧 |

負荷の正体はたいてい「**複数のものが、それぞれ違う状態にあって、頭の中で追いきれない**」ことなので、どの場面でも状態表が中心に来る。

### 2. 形を選ぶ

上の表から引けないときは、**読み手がそこから何を取り出すか**で選ぶ:

| 取り出すもの | 形 |
| --- | --- |
| 順序 — いつ何が起きたか | 線形タイムライン |
| 全体の現在値 | 数値の一覧（レールに縦積み） |
| 個々の状態 | 状態表 + チップ |
| 関係・依存 | 有向グラフ |
| 量 — 並べただけでは形が見えないとき | チャート |

**チャートは点数が多いときだけ。** 2 個なら文中に書き、3〜5 個の比較は表で足りる。時系列と分布だけがチャートに値する。

**何がどの分類に属するかは表で書く。** ベン図は使わない。ただし「表では分かりにくい」と言われたときだけ、3集合を上限に特別対応する（4集合は円では正確に描けない。各領域のラベル位置は重心を計算して手で置く）。

### 3. ページを組み立てる

`assets/build.sh` で組み立てる。**ライブラリ本体はこのスクリプトが結合するので、コンテキストを通らない。** 配置されたファイルに実行ビットは付かないので `bash` 経由で呼ぶ。

```bash
bash ~/.claude/skills/work-map/assets/build.sh \
  -o ~/Claude/scratch/<題名>.html \
  -c <本文の断片> -t "<タイトル>" [-g <グラフデータ>] [-s <時系列データ>]
```

書くのは本文の断片とデータだけで、CSS・骨格・ライブラリには触らない。骨格は次の順に並べる:

1. レール（左に固定） — 状態カウント・セクション目次・更新日
2. `.masthead` — 見出しと1段落の要約
3. `.next` — 次の一手を1つだけ
4. 負荷の原因を解く主役の形
5. 経緯（そこへ至った理由。**調査と決定だけを残し、試して捨てた道は書かない**）
6. 論点表

**同じ数値を2箇所に置かない。** レールにカウントを出したら本文側に再掲しない（更新のたび両方を直す羽目になる）。

データファイルの形は `assets/render-graph.js` と `assets/render-chart.js` の冒頭コメントにある。

### 4. 検証する

**目で見て分かる欠陥と、計算しないと分からない欠陥の両方がある。** 両方やる。

```bash
# 外部参照は 0 でなければならない（href はページ読み込み時に通信しないので対象外）
grep -cE '<link|@import| src=' <出力>

# タグの開閉が揃っているか
python3 -c "
import re,sys
h=open(sys.argv[1],encoding='utf-8').read()
for t in ['tr','td','th','tbody','table','div','section']:
    o=len(re.findall(r'<%s[ >]'%t,h)); c=len(re.findall(r'</%s>'%t,h))
    print(t,o,c,'OK' if o==c else 'NG')
" <出力>
```

- **レールのカウントと表の行数が一致するか。** 状態を1つ動かしたら両方を直す。
- **文字色を変えたらコントラスト比を計算する。** ラベル類は 0.7rem（約 11px）と小さく、WCAG の 4.5:1 が要る。スクリーンショットでは判定できない。
- **チャートの目盛り上限が最大値以上か。** 複数の値域で検算する。上限が max を超えないと最大点が枠外に出る。
- **描画して見る。** レイアウト崩れ・要素の重なり・はみ出し・ラベルが隣の領域へ食い込む類は、開いて見るまで分からない。

### 5. 更新する

**起動したあとは、なるべく最新に保つ。** 一度作って放置しない。作業が進むたびに反映するが、変更の大きさで扱いを分ける:

| 変更 | 扱い |
| --- | --- |
| 状態の遷移、行の追加、数値の更新、経緯への1件追加 | 確認を取らず、その場で高頻度に反映する（部分編集） |
| ブロックの追加・削除、構造の変更、全体の書き直し | 要件を固めて確認を取ってから（再ビルド） |

境界は**部分編集で済むか、全体を組み直すか**。組み直しはページ全体のトークンを毎回払うので、そこに確認の関門を置く。

## 出所の種類

状態（解決したか）とは**別の列**に置く。混ぜると「確定しているが推測に基づく」という最も危ない組み合わせが表現できなくなる。

| 出所 | 意味 |
| --- | --- |
| リンク | 一次情報がある。Slack のメッセージ、設計書、PR の該当箇所、main 上の実装位置、チケット |
| 実測 | 自分で計測・実行して確かめた |
| 合意 | 関係者と決めた。会話が出所でリンク先は無い |
| 推測 | 根拠が弱く、裏取りが要る |
| — | まだ何も無い |

- ラベルは短くする（`PR #123`、`設計書`、`SRE-4821`）。URL をそのまま貼ると負荷を上げる側に働く
- コード位置は**コミット SHA を固定した permalink** にする。ブランチ相対のリンクは行がずれて別の場所を指すようになる
- **テキストリンクに限る。** favicon やプレビュー画像を出した時点で外部通信が発生し、自己完結が壊れる

## 状態の種類

記号・語・色の3つで示し、色だけに載せない。該当する実データが無い状態は使わない。

| 状態 | チップ |
| --- | --- |
| 確定 | `chip settled`（✓） |
| 未確定 | `chip open`（?） |
| 要注意 | `chip warn`（⚠） |

有向グラフのノードも同じ区分を使う。`settled` が確定した前提、無印が導かれる帰結、`open` が未確定（破線で示すので色覚に依存しない）。

## 渡す・残す

既定は破棄だが、そこから先の経路が2つある。どちらも `~/Claude/scratch/` の外へファイルをコピーするだけで、公開ページは介さない。

- **渡す** — 単一ファイル自己完結なので、添付でもコピーでもそのまま開ける
- **残す** — リポジトリに置くなら、その時点で扱いが変わるので commit 対象にする

Artifact として publish しない。公開したページは元ファイルを消しても残り、破棄が既定という前提と噛み合わない。
