# work-map — なぜこの形なのか

手順と規則は [SKILL.md](SKILL.md) にある。ここに残すのは**そう決めた理由**と、判断の根拠になった実測値。同じ検討を繰り返さないための記録なので、結論だけを知りたいときは読む必要がない。

## 何を解こうとしたか

複雑な仕事の経緯・状況・依存関係を HTML にまとめる場面が増えたが、毎回ゼロから形を決めていた。共通のフォーマットを skill にすれば、形を考える手間が消えて内容に集中できる。

途中で分かった一番大きいことは、**このページがいつ読まれるか**だった。作業の再開時でも他人への説明用でもなく、**認知負荷が高くなったとき・理解が及んでいないと感じたとき**に読む。ここから設計の芯が決まった。ページの仕事は記録ではなく、頭に収まらなくなったものを外に出して見えるようにすることで、だから情報は増やすのでなく減らす方向に働く。

## 調べたこと

### Claude が推奨する作り方

- 組み込みの design skill が artifact 構築時に自動で効き、**まずプロジェクトのデザインシステムを探す**
- 優先順位は プロンプト > プロジェクトのデザインシステム > Claude 自身の選択
- 公式ドキュメントが「繰り返す artifact プロンプトは skill にせよ」と明示している

ただし**この skill は artifact を publish しない**ので、組み込み skill が意匠を尊重する経路は当てにできない。そのため意匠は `assets/head.html` のテンプレートに持たせ、そこを唯一の出所にした。SKILL.md に CSS を散文で書くと、生成のたびにモデルが再構成してブレる。

### shadcn/ui は使えない

Tailwind CSS が必須と明記され、コンポーネントは `.tsx`。ビルド工程を前提とする以上、単一ファイル自己完結とは両立しない。転用したのは視覚語彙だけ — CSS カスタムプロパティによるトークン命名、角丸スケール、中間色の階調。

## 制約とその根拠

| 制約 | 根拠 |
| --- | --- |
| ローカルの単一 HTML のみ。publish しない | 公開ページは元ファイルを消しても残る（自動削除は Team/Enterprise の管理機能）。破棄が既定という前提と衝突する。加えて claude.ai へのアップロードが発生しない |
| 外部リクエスト 0 | ファイルで渡す・オフラインで開くため。CDN 参照が1つでもあると渡した先で壊れる |
| 完全な HTML ドキュメントとして書く | Artifact なら publish 時に外殻が被さるが、ローカルには無い。`charset` 宣言を欠くと `file://` で日本語が化ける |
| mermaid を使わない | claude.ai の viewer 側の機能で、ファイルで渡した先では素のテキストになる |
| フォントを埋め込まない | 日本語なので CJK カバレッジが要り最低でも数百 KB。更新のたび全体を再出力する使い方では、これが最大の恒常的トークンコストになる |
| 書き先は `~/Claude/scratch/` | リポジトリに書くと commit 事故になる。ディレクトリ名が使い捨てを語る。パスが短く辿れ、セッションを跨いでも残る |

フォントの1点は、組み込み design skill が指示する「`@font-face` を data URI で埋め込む」を**意図的に外している**。ラテン専用フォントを前提にした指示で、日本語では成立しない。

**社内限定の共有はファイル経路でしか成立しない。** 組織内スコープの共有は Team/Enterprise の機能で、Pro/Max では公開リンクしか選べないため。

## なぜ出所を持たせるか

出所を辿れれば情報の価値を評価できる。「この主張はどれくらい信じてよいか」を読むたびに思い出さずに済むので、認知負荷を下げるという目的に直接効く。

**一次情報が無い場合を明示するのが肝。** リンクが無いものが「まだ調べていない」のか「自分の判断」なのか「根拠の弱い推測」なのか区別できなければ、価値の評価はできない。

## 図をどう選んだか

### 有向グラフ — dagre を同梱する

当初は「レイアウトエンジンが無いので層状に並ぶ依存しか描けない」という制約を置いていたが、**これは実測せずに決めたものだった**。外部リクエスト 0 は CDN を禁じるだけで、ライブラリをインラインに埋め込めば満たせる。

| 項目 | 実測値 |
| --- | --- |
| `@dagrejs/dagre` 3.0.0 | 39 KB（依存は `@dagrejs/graphlib` のみ） |
| ライセンスヘッダ | 1.3 KB |
| 19 ノード・18 エッジのページ全体 | 47 KB |

**ライブラリはトークンを消費しない。** `assets/build.sh` がファイルを結合するので、97,200 バイトのコードが会話を通ることはない。組み立てを手順の散文でなくスクリプトにしたのは、次のセッションが同じ手順を再導出してライブラリをインラインに出力する事故を防ぐため。

**ライセンス。** dagre・graphlib とも MIT（Chris Pettitt, 2012-2014）。再配布の条件は著作権表示とライセンス全文を複製物に含めること。v3 は minify の際にライセンス表示が落ちているので、生成物の冒頭にヘッダとして付ける。**v1 系は BSD-3-Clause の文言も抱えているため使わない**（除去前の lodash 由来と見られる）。

mermaid も同じ方法で埋め込めることは確認したが採らない。3.5 MB と 90 倍近い上に、描画までライブラリが行うのでノード幅が不揃いになり、状態の色分けが消える。状態を見分けさせたいので、意匠の制御を手放す取引が割に合わない。

### チャート — ライブラリを使わない

46 点の時系列を、スケール変換・目盛りの丸め・ラベルの間引き・面と線のパス生成まで含めて **74 行**で描けることを実測した。

依存グラフとは必要な計算が違う。グラフのレイアウトは交差を減らす最適化問題で自前は非現実的だが、チャートの座標変換は値域をピクセル域へ写す線形写像で、書ける。dagre を入れた必然性はチャートには無い。

必要になったら `d3-scale`（15 KB・ISC）を足す。判断点は**目盛り生成が込み入る要求**が出たとき — 対数軸、時間軸の自動目盛り、積み上げなど。描画まで行う uPlot や Chart.js は canvas なので SVG の意匠と別世界になり、採らない。

自前の代償は境界のバグを踏むこと。実際、最初の実装は目盛りの上限が最大値を超えず、ピークが枠外に出ていた（`max 17` に対し `top 15`）。`d3-scale` の `nice()` が正しく扱う部分にあたる。

**チャートが要るのは、数値を並べただけでは形が見えないときだけ。** 2 個なら文中に書けばよく、3〜5 個の比較は表で足りる。5つのユースケースのうち時系列が要るのは障害調査と進行管理の2つで、残りは横棒に落ちる。

### 集合の重なり — 表を既定にする

3集合で並べて比べたところ、速さは問いによって割れた。要素や属性を1つ指して引く問い（「レビューはどの図を使う？」）は表が速く、重なりや存在しない組み合わせを問う問い（「両方使うのは？」「使わない場面はある？」）はベン図が速い。

それでも既定を表に置いたのは次の2点による。

- **ベン図が勝つ問いは一度分かれば済む。** 「状態表を使わない場面は無い」と分かればその図の役目は終わる。作業中に繰り返し引くのは要素起点の問いのほう
- **要素が増えるとベン図だけが壊れる。** 表は行が伸びるだけだが、ベン図は領域に文字が入りきらない。1領域2件で改行が要り、3〜4件で破綻する

使うことになった場合の制約: **3集合まで**（4集合は 16 通りの領域が要るのに円 4 つでは 14 通りしか作れず、対角どうしだけが重なる領域が存在しない）。**ラベル位置は自動化できない**ので領域の重心を計算して配置する。

## デザインの根拠

### 色

- **地** — 藍に寄せたニュートラル `#f3f5f3`。純グレーを避け、アクセント側へわずかに寄せる
- **文字は3段** — 見出し `#141a1c`（比 16.05）／本文 `#33403f`（9.85）／ラベル `#667073`（4.64）。本文を薄い灰色に置くと見出しとの差が開きすぎて弱く見えるので、地との差はしっかり取り、階調は見出しとラベルの側で作る
- **アクセント** — 藍鉄 `#186a83`。1色のみ
- **状態色** — good / warn / serious の3段をアクセントとは別系統に予約する。critical は当初4段目として置いたが、この用途に該当する実データが無く未使用のまま残ったので外した
- **単一テーマ（ライト固定）** — 作業中に読むだけのページに2組のトークンは要らず、定義が4ブロックから1ブロックに減るぶん再出力も軽くなる

**コントラストは計算しないと分からない。** 最初に置いた `--ink-3` は 3.37 で WCAG 不合格だったが、スクリーンショットでは気づけなかった。`#667073`（4.64）へ修正済み。

### レイアウト

**行長の制限は本文にだけ掛ける。** 読み物の1行は 40rem で頭打ちにするが、図・表・タイムラインは画面の広さをそのまま使う。ページ全体を1つの狭いカラムに収める作りは、ワイドディスプレイで**画面の3分の1しか使わない**。

骨格は左に固定レール、右に本体の2カラム。スクロールしても現在地が見えるので、レールにカウントを置いたら本体側に再掲しない。

## 未確定の論点

1. **同梱ライブラリの更新** — dagre v3.0.0 をバージョン固定で抱えるので、不具合や脆弱性が出ても自動では上がらない。更新の契機を決めていない
2. **図の型を5種で打ち止めにするか** — 5つのユースケースはいずれも線形タイムライン・数値の一覧・状態表・有向グラフ・チャートで説明できたが、実際に使ってみるまで足りるかは分からない
